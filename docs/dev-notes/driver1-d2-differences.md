# Driver 1 vs Driver 2 LEV: differences and conversion notes

Living notes for the D1 -> D2 converter (`src_rebuild/d1dlc`). Update it whenever a part teaches something new, so the next city only needs the converter, not new research. Measured on MIAMI (D1) and CHICAGO (D2) unless a city is named. Plan: `plans/driver1-cities.md`.

Strategy (user, 2026-10-11): convert ONE city completely first (Miami: textures, models, cells, heights, road graph, traffic, cops, peds, on foot), note every finding here, then run the same converter on Frisco, LA, New York, Newcastle and Training. City-specific fixes go into a per-city table in the converter, everything else must be generic.

## 1. Container (identical in D1 and D2 unless noted)
- `LUMP{37,2040}` + `OUT_CITYLUMP_INFO` (8 ints: loadtime/tpage/inmem/spooled offset+size), rest of the 2048-byte header is filler (D2: `DES!` repeated; D1: a table, never read by the game).
- Sections start on 2048-byte sectors, padded with zeros: loadtime (`LUMP{35,size}` + sub-lumps), tpage section (permanent pages, no lump header), inmem (`LUMP{36,size}` + sub-lumps), spooled section (no lump header, offsets in sectors).
- Sub-lump list: each `LUMP{type,size}` + data padded to 4 bytes. D2 ends with `LUMP{255,0}` (counted in the section lump size); D1 starts with an `int` count instead. The game (`ProcessLumps`) reads until type 255 and also knows the D1 road lumps.
- The game only reads the first 8+32 bytes of the header for `citylumps` (system.c), everything else is addressed through those offsets.
- Chicago has 1.66 MB of special-car blocks after the spooled section (read at sector `0x1400 + n*42`, spool.c). D1 has no such tail.

## 2. Textures
- `TEXTURENAMES` (null separated) and `TEXTUREINFO` (`int pages, int textures, TP[pages+1], per page: int n + n x TEXINF(8 bytes), int nperm + XYPAIR[16], int nspec + XYPAIR[16]`) have the same layout in D1 and D2. `TP.flags/offset` are never read by the game; D1 flags contain leftover garbage in the high bits (`0x289d0051`), ignore.
- Permanent pages (`permlist`: x = page index, y = byte size) are stored back to back in the tpage section, each padded to a sector; page data = `int npalettes`, 32 bytes per CLUT, then the compressed 64x256 page (`decomp_asm`). Same codec in D1 and D2.
- VRAM: 19 tpage slots (`tpageslots`), permanent pages and special pages use the first slots, spooled area pages the rest. Miami 7 permanent, Chicago 11 + 2 special.
- D1 permanent pages mix world and car textures (page 3: `BCK1 FNT1 BON ...`, page 4 `POLICE ARM1 CHEST1 JEANS1`); D2 keeps car pages separate (`carTpages`, `specTpages` in texture.c).
- D1 spec list = player car pages (Miami 8 pages). Converter sets `nspec = 0` until Part 6.
- Names the D2 engine looks up that D1 lacks (Miami): textures `FLARE HEAD1 LENSFLR LIGHT OVERHEAD SKYMOON TSHADOW` (Frisco also `SEA`); D1 names its flare `FLARE1`. These come from the donor CHICAGO.LEV pages (Chicago permanent page 2 has `FLARE LENSFLR LIGHT SMOKE LITTER`, page 51 has `OVERHEAD`).

## 3. Models
- `MODELS` lump: `int count`, then per model `int size` + data (size 0 = not resident). `MODELNAMES` = one null-terminated string per model index (empty string for unnamed), count = model count.
- `MODEL` struct (36 bytes) identical; vertex/normal/poly offsets are relative to the model start.
- Model names the engine needs that D1 lacks (Miami + Frisco): Tanner parts `HEAD NECK TORSO HIPS U_ARM_* L_ARM_* HAND_* THIGH_* CALF_* FOOT_*`, `HUB GREENCONE CAR FRAME LORRY ELTRAIN`; Jericho and event props are not needed in D1 cities. Take from the donor, append at indices >= D1 count (limit `MAX_MODEL_SLOTS` 1536).
- D1 `MODEL_FLAG_GRASS` and some flags2 bits differ from D2 (ODE: "D1 flag is DIFFERENT"). Still to map in Part 2 (spike histograms in `d1spike.py`).
- World poly types in D1: 10, 11, 20, 21 as D2 plus 16/17 (flat colour), 22/23, 5, 8, 9, 1. D2 `draw.c` only plots 11/21/23. D1 car polys: 0, 1, 20-23 (D2 cars only triangles 0, 20, 22).

## 4. Spatial data (Part 3-5 facts, summary of plan 2a/2b)
- D1 cell 3000 units, region 30 cells; D2 cell 2048, region 32 cells; heightmap 64x64 cells of 1024 per D2 region.
- D1 roads are all axis aligned (no curves); road ids in the road map use high bits `0x0xxx` road, `0x4xxx` junction, `0x8xxx` unknown (still open).
- D1 heights come from the road map value + `ROADSURF` polygons; D2 from per-region sdPlane grid.

## 5. Engine facts learned while wiring the cities (Part 1)
- Tables indexed by `GameLevel`: LEV-bound data uses the real city, look/sound data uses `CityBase[]` (mission.c). D1 rows of carTpages/specTpages/SpecialByRegion/overlaidmaps copy Chicago until the converter generates them.
- `LoadMission` copies `GameLevel` from the mission header; D1 Take a Ride keeps the selected city (mission 50/51, Chicago start position).
- Events, env sounds, tunnels stay off for D1 cities; `GameLevel 4` is also used by the frontend for the finale cutscene, so never rely on `GameLevel` outside a running game.

## 7. Part 2 findings (container, textures, models, small lumps) - measured on all six cities

Converter: `src_rebuild/d1dlc/d1_convert.cpp` (`D1Dlc_ConvertLev`, `D1Dlc_CheckLev`), writer `lev_writer.cpp`. CLI: `d1conv repack|check|convert`.

- **Writer verified:** `d1conv repack` of CHICAGO.LEV is byte identical except 8 alignment-pad bytes (retail files hold stack garbage after some lumps). The game runs the repacked file.
- **Spec list:** the `TEXTUREINFO` special list is after `XYPAIR perm[16]` (128 bytes). `d1spike.py` read it at +64, its "special" counts were wrong. Real values: Chicago 10, Miami 8, New York 10.
- **Textures/tpages:** D1 tpage data, `TEXINF`, names are used unchanged. D1 special pages (player/cop car pages) are dropped for now (`nspec = 0`); Part 6 decides how D1 cars get their pages and palettes.
- **Donor pages** (Chicago permanent pages, appended after the city pages, polygons of donor models remapped): 1 (ped head, SEA), 2 (FLARE, LENSFLR, LIGHT, SKYMOON, SMOKE, GREENCONE), 50 (wheels, hubcap), 58 + 63 (Tanner). 5 pages -> Miami 12, Frisco 14, LA 11, New York 13 permanent pages. VRAM has 19 slots and D1 areas need 4-7 spooled pages, so max ~13 permanent pages. Page 51 (OVERHEAD, overlay map) is NOT merged yet (Part 7).
- **Newcastle (CREDITS) and Training (TRAIN) do not fit:** all their pages are permanent (up to 16 in the perm list). Converting them needs fewer donor pages or dropping unused permanent pages (decide when they are converted).
- **TSHADOW** does not exist in D1: it becomes an alias entry (extra `TEXINF`) of CARSHAD, which exists in every D1 city on a permanent page. Every other missing name is in a donor page.
- **Models:** `MODEL` struct and polygon layouts equal D2 (byte 3 of 10/11/20/21/22/23 is 0 in both). The only change is clearing `flags2` bit 0 (D2 uses it at runtime as the animated-object flag; D1 sets it on 18 Miami models). Donor models are appended at index = D1 model count (17 models: Tanner parts, ped head, wheels, hubcap, GREENCONE).
- **Polygon types not drawn by the D2 world renderer:** 1, 5, 8, 9, 16, 17 (flat colour or unknown). Miami has 64 type-5 polygons (probably textured quads, layout like type 21) - convert them once the city renders (Part 3) and the picture shows what is missing.
- **Car models:** D2 `buildNewCarFromModel` (cars.c) already handles polygon types 0, 1, 18, 19, 20, 21, 22, 23, so the D1 `CAR_MODELS` lump is copied as is, no quad splitting needed. Open: `GetCarPalIndex(tpage)` maps a car page to a palette slot through `carTpages[GameLevel]` (texture.c) and `civ_clut[carid][texture][palette]` has fixed size, so the D1 pages and the D1 `PALLET` lump need a proper mapping in Part 6. `PALLET` is written empty until then (`total_cluts = 0` makes the engine skip it).
- **LOWDETAIL:** `ushort high[N]`, `ushort low[N]`, N = model count, `0xFFFF` = none. D1 identical, extended with `0xFFFF` for the donor models.
- **OVERLAYMAP:** D1 = 164 offset shorts + CLUT at 328 + RNC tiles; D2 = 256 offset shorts + CLUT at 512. Converted by shifting offsets by 184; the end of the D1 offset table holds leftovers (offsets outside the lump), those entries point at the first tile. Map scale/offsets (`overlaidmaps[]` in overmap.c) and the OVERHEAD page are Part 7.
- **CHAIR:** 12-byte entries `{int x, int z, short rotation, char index, char pad}`, list ends with `rotation == 9999`. Identical in D1 and D2, copied.
- **SUBDIVISION:** the engine ignores it (stub), not written.
- **MOTIONCAPTURE:** D1 has 4 lumps, D2 needs 14 (Tanner + pedestrians): all 14 come from the donor.
- **Names the engine looks up** (checked by `d1conv check`): textures FLARE HEAD1 LENSFLR LIGHT SKYMOON SEA TSHADOW SMOKE DEBRIS LITTER SKID SKYSUN DROP DIGIT JEANS1 ARM1 FOREARM1 CHEST1 LOWHEAD LIGHTREF SWBIRD1 SWBIRD2; models: Tanner parts, PEDHEAD1, GREENCONE, wheels, HUBCAP1. COLLON, COPLIGHT, SPLASH, ROTOR are missing in Chicago too (engine falls back).

## 8. Part 3 findings (cells, regions, spool) - Miami, Frisco, LA, New York

Code: `src_rebuild/d1dlc/d1_map.cpp` (`D1Dlc_ConvertMap`, `D1Dlc_CheckMap`), wiring in `d1dlc.cpp` (`D1Dlc_ConvertCity`: converts at first use, per city stamp `DRIVER1\CONVERTED\<NAME>.VER`, `D1DLC_CONVERTER_VERSION` bump forces reconversion). Conversion takes 0.12 s per city. Debug: `d1conv convert` + `d1conv check` (also checks MAP/SPOOLINFO/regions, valid on retail Chicago).

- **D1 region layout** (`Spool` 12 bytes, same struct as D2): spool data order is `roadm` (RLE short length + ushort road id, 60x60 road map cells), `roadh` (RLE uint length + uint value), cell pointers, cell data, cell objects. D2 order is cell pointers, cell data, cell objects, then one road block (`cell_data_size[1],[0],[2]`, `roadm_size`).
- **D1 cell pointers:** `int size, int packtype` + entries for 30x30 = 900 cells (D2: 1024). Pack types 0 empty, 1 plain `ushort[900]`, 2 bit coded (code word per 16 cells, then the pointers of the set bits). Both formats: pointer = region local index into the cell data array; the engine adds the barrel's `slots_add`.
- **D1 cell data:** `{ushort num, ushort next_ptr}` linked list (next_ptr includes the barrel `slots_add`, 0xFFFF ends). D2: `ushort num` list, contiguous, the last entry has bit 0x8000 (bit 0x4000 = level list header, unused here).
- **Object index space:** `num & 0x3FFF`: `< num_straddlers` = MAP lump object, else `num_straddlers + objects_add[barrel] + local index`. Per barrel counts in SPOOLINFO are the max object sectors (D1 128 objects per sector of 16 bytes, D2 256 per sector of 8 bytes); the whole space must stay below 16384.
- **Barrel** = `(regionX & 1) + (regionZ & 1) * 2`; the four barrels hold the 2x2 loaded regions.
- **D1 object lists are footprint based** (about 2 cell references per object, only 54% of the references sit in the cell of the object centre). The converter ignores them: all unique objects (duplicates by position/type/yang merged) are put in every D2 cell their bounding sphere square touches (radius capped at 6144). An object inside one D2 region is local, otherwise a straddler. Miami: 58 453 objects, 368 201 references, 5 011 straddlers, index space 12 179 of 16 384.
- **Grid:** the same world rectangle centred on the origin (D1 `cells_across/2*3000`), rounded up to an even number of 32-cell regions. Miami 448x640, Frisco/LA 832x832, NY 704x704 cells. World positions stay unchanged. The engine takes cell and region size from `cell_header` on PC, but the height map shifts (`>> 16`, 64x64 cells of 1024) are fixed, so D2 sizes are required.
- **Packed cell object:** `x, z` = low 16 bits of the world position, `vy = y*2 | (model bit 10)`, `value = (model & 1023) << 6 | yang`. Positions are restored relative to the iterated cell, so an object must be listed only in cells within 32768 units of it.
- **Road block per region** (loaded at `PVS_Buffers[barrel] - 4`): `int cbr`, PVS (1025 big endian ushort offsets + encode table, all offsets 0 = every cell visible), then at `pvs + cbr` the height map: `short [0]=2, [1..3]` byte offsets of planes / BSP lists / nodes, 64x64 plane indices, planes. Part 3 writes one flat plane (`b = 0x4000, d = 0` = height 0). SPOOLINFO `pvs[barrel]` must be at least the road block size.
- **Areas** (`AreaDataStr`, tpage block 17 sectors per page, model block of `[int size][MODEL]` models plus a last sector `ushort count, ushort model numbers`) are copied from D1 with new sector offsets. Unused slots hold junk (Miami area 3: 164 pages): emptied. Music/ambient fields are unused by the PC engine and zeroed. D2 regions inherit `super_region` / connected areas from the D1 region at their centre. Coverage check in the log: spooled models needed by a region but absent from its area (Miami 12 of 107 regions pairs 12; unresolved models draw nothing, `dummyModel`). Better area assignment is a later improvement.
- **flags2 bit 0** (animated object in D2) must also be cleared in the spooled model blocks, otherwise `DrawAllAnimatingObjects` dereferences the empty D1 animation table (crash in LA).
- **Sky:** models 0..3 must be the D2 sky dome layout (30 vertices, 20 quads, `PlotHorizonMDL` loops over `num_vertices / 3`); D1 `SKY01..04` have 20 vertices and crash the renderer. The converter takes `BASE1..4` from the donor and clears their texture page; the sky textures come from `LoadSky` files of `BASE_CITY`.
- **Overlay map:** `overlaidmaps[]` rows of D1 cities have `toptile 0` (flat dummy colour) until Part 7, the D1 tile table makes `UnpackRNC` read garbage.
- **Empty road lumps** (STRAIGHTS2, CURVES2, JUNCTIONS2_NEW with count 0) are written so `gDemoLevel` and the road tables are initialised; Part 5 fills them.
- **Test:** Miami at world position 117000, -21000 (`-startpos 117000 -21000`) shows textured road, overpass, traffic light and shops; the player car is black (palettes, Part 6). Start at -6750, -444000 (D1 road 0) shows only grass: no objects there. Cities 4..7 run 60 s under cdb without crash.
- Task for Part 7: Miami start positions per city (centre of a long straight).

## 9. Part 4 findings (heights and surfaces) - Miami, Frisco, LA, New York

Code: `src_rebuild/d1dlc/d1_height.cpp` (oracle `D1HeightField`, writer `BuildRoadBlock`, engine side reader `SampleRoadBlock`), road map loading in `d1_map.cpp` (`LoadRoadMap`). Check: `d1conv heights <D1.LEV> <converted.LEV> [step]` (also run by `d1conv convert`): compares the oracle with the engine lookup of the converted file on a grid.

- **D1 ground oracle** (port of OpenDriverEngine `FindSurface`): road map cell = 1500 units, `cpos.x = (unitXMid + vx) / 1500`, `cpos.z = (unitZMid - (vz - 750)) / 1500`, `unitXMid = (width + 1) * 750`, `unitZMid = height * 750` (ROADMAP lump). Cell value: low 16 bits height, bits 16..25 road tile model, bits 30..31 rotation (x 1024). Ground `y = -height` (D2 convention, negative up). A tile model with SURFACEINFO polygons (ROADSURF lump, polygon stride 52 bytes, not 50) adds a slope: local coords `px, py` from the position inside the tile, rotated by the tile rotation, `y = ((px * a + py * c) / 4096 - d) - height`.
- **Region road map layout:** region (rx, rz) holds the global cells `x = 60 * rx + i`, `z = 60 * (regionsDown - 1 - rz) + j` (z is mirrored). Absent regions have no data.
- **Surface ids:** D1 road id `< 0x4000` = road, `0x4xxx` = junction, `0x8xxx` and `0xFFFF` = none. D2 plane surface = `32 + road id` or `32 + 0x2000 + junction id` (so Part 5 must keep the D1 road / junction numbers as D2 straight / junction indices), otherwise SURF_WATER 6 (model `SHAPE_FLAG_WATER`), SURF_GRASS 4 (model `flags2 & 0x4000`) or 0.
- **D2 height cells are shifted by 512 units** against the object cells: cell `i` of a region window covers world `X0 + 512 + 1024 i`, the window of the region in barrel b serves positions `[X0 + 512, X0 + 66048)` (`(vx - 512) >> 16`). BSP coordinates are local to the cell, planes use `x' = vx - X0` (equal to the engine's `((vx - 512) & 0xFFFF) + 512`). Regions whose window overlaps D1 data must be written even without objects.
- **BSP:** node = 4 byte int, bits 0..10 angle (11 bit signed), 11..22 dist (12 bit signed), 23..30 offset (8 bit signed), bit 31 = split. Child 0 follows the node, child 1 at `node + offset`; `dot = z * cos - x * sin < dist * 4096` -> child 0. Axis splits: angle 0 on z, angle -1024 on x. Leaf = int plane index. Grid value: plane index, `0x4000 | node index`, -1 sea; `0x2000 | n` multi level (unused). The header offsets are 16 bit: planes + the 4 byte list stub must start below 32768 -> at most 2046 planes per region, nodes go last (index < 16384).
- **Fit:** per height cell the D1 road map lines (1500 grid) split the cell, each rectangle is fitted with a plane (3x3, 5x5 on slope tiles, samples 24 units inside: D1 tile edges carry slivers of wrong heights). Rectangles are split further (depth 6, min 256 units) while the error is above 20 on roads (surface >= 32) / 48 on other ground. A rectangle with one surface and a good fit stays one leaf across D1 cells. Flat planes `b = 0x4000`, `d = -y`; sloped `b = 4096`, `a = -slope * 4096`, `c`, `d` from the mean. Planes are quantised (height 4, slope 32 units, terrain twice as coarse, coarser steps per region when 2046 planes are exceeded), cells that need more than the node space are retried with a looser tolerance.
- **Results** (`d1conv convert`, 0.4 to 0.7 s per city): Miami 4 450 planes / 262k nodes, roads max error 33; Frisco 27k planes, roads max 15, terrain up to 63 (cliffs); LA roads max 10; New York roads max 17. Surfaces identical in all samples. Frisco and New York terrain keeps some larger errors at cliffs / overflow cells (non road).
- **No multi level cells:** the D1 road map has one value per cell, so D1 cities have no drivable layer under a bridge; bridges and viaducts are one layer plus cell objects whose model collision boxes block cars. Test by driving: not done yet.
- **Test:** Miami at 117000, -21000 (car on the road), 175800, -90300 (car floats on the bay at its water level). Cities 0 and 4..7 run 50 s under cdb without crash.

## 10. Part 5 findings (road graph) - Miami, Frisco, LA, New York

Code: `src_rebuild/d1dlc/d1_roads.cpp` (`D1RoadTable::Build`, lump writers, `D1Dlc_CheckRoads`), pavement + straight index in `D1HeightField::Eval` (`d1_height.cpp`).

- **D1 roads**: `ROADS` (16 byte `DRIVER1_ROAD`, id == index in all cities), `JUNCTIONS` (44 byte, id == index), `ROADBOUNDS` (axis aligned boxes, `dir` 1 = long side along x, 0 = along z, cell coordinates relative to the middle of the road map: `cell = bound + width / 2` and `+ height / 2`). Road cells of the road map lie exactly inside their bounds (all four cities), junction squares are `0x4000 | id` cells (2x2, 3x3 cells), and **`0x8000` cells are the pavement** (one cell wide strip beside the road, id bits 0).
- **Lanes**: D1 `NumLanes` = cells across (1, 2 or 3, equal to the road width in cells); `LaneDirs` has one bit per lane (bit set = against the road direction), lane 0 on the right of the direction of rising road map coordinates. D2 `NumLanes` counts pairs of 512 unit lanes, `LaneDirs` / `AILanes` one bit per pair. Mapping used: D2 NumLanes = D1 lanes (cars use lanes of 512 units inside the 1500 unit D1 lanes), pair j = D1 lane j, direction bits copied; z roads are flipped (D2 angle must be < 2048, so angle 0 = +z while D1 rising map z = world -z): pair j = D1 lane N-1-j, bit inverted. AILanes = all pairs. Parking flags (D1 `flags` bit 0), speed limit bits and traffic lights are not converted yet (junction flags 2 = priority rule only).
- **Straights**: world position of a road map cell: `x = cx * 1500 - unitXMid` (cell start), `z = unitZMid - cz * 1500` is the cell centre, so Midx / Midz / length come straight from the bounds. D2 `length` is a ushort: roads longer than 40 cells (D1 roads reach 311 cells) are cut into equal pieces of at most 40 cells (60000 units, Chicago's maximum is 61440). The plane surface of a road cell is the index of its piece (`D1RoadTable::StraightIndex`, so the surface ids of Part 4 changed from road id to straight index). Pieces link to each other with `ConnectIdx` (ahead [0] [1], behind [2] [3]); the outer ends link to `0x2000 | junction id`.
- **Junctions**: `DRIVER2_JUNCTION.ExitIdx[k]` = straight next to the junction in direction k, k = 0 +z, 1 +x, 2 -z, 3 -x (heading k * 1024). The D1 entry order of `DRIVER1_JUNCTION.entries[k]` is the same order (checked: 0 exits in the wrong direction in all four cities), so the entries are copied. Junction `type`, `lightsTimer` etc. are unused so far (LA's `type` field holds garbage).
- **Pavement for pedestrians**: `pedest.c IsPavement` wants surface 12 (`GetSurfaceIndex == -20`) and a road in the same height cell; Chicago uses 12 for pavement tiles. D1 `0x8000` cells now get surface 12 (water wins).
- **Checks**: `d1conv convert` logs the road table (roads, splits, junction side conflicts, exits not touching their junction, wrong directions) and `D1Dlc_CheckRoads` verifies the written lumps (indices in range, links reciprocal): 0 problems in Miami, Frisco, New York, LA (1 exit of LA does not touch its junction: data oddity).
- **In game** (temporary telemetry, removed): Miami 117000,-21000: 13 civ cars (engine limit of this mission), 0 confused in 95 s, traffic mostly on the right side of the road (right 6-7, left 0-2 of 7-9 measured), felony 4500 gives roadblocks and pursuit cops; 15 pedestrians ping in on the pavements; Tanner leaves the car (Return) and re-enters; car drives through junctions, hits buildings / poles (damage rises, speed bounces back). Frisco 42750,2250 and New York -77250,-33750: 12-13 civ cars. LA: civ cars only appear while driving (roads far apart), then 10-11.
- **Not done**: parking, traffic lights, speed limits, curves (none in D1), cop road blocks placement quality, left / right check of lanes by eye.
