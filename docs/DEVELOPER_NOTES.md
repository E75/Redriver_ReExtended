# Developer notes (engine findings, formats, test options)

Reverse-engineered Driver 2 (C/C++, PsyCross = PSX API layer on SDL2/OpenGL). This branch adds the Driver 1 cities as an optional DLC; the working plan is `dev-notes/driver1-cities.md` (read it first, its section 0 holds the status).

## Layout
- `src_rebuild/Game/C/*.c` — game logic (decompiled PSX code, compiled as C++). Frontend: `src_rebuild/Game/Frontend/FEmain.c`.
- `src_rebuild/redriver2_psxpc.cpp` — PC entry: `config.ini`, key handlers, startup (calls `D1Dlc_Detect`).
- `src_rebuild/d1dlc/` — Driver 1 DLC library (LEV reader, city table, detection; converter grows here). `src_rebuild/tools/d1conv/` — `D1Conv` developer CLI + `spike/d1spike.py` format analysis script.
- `src_rebuild/PsyCross` — submodule, upstream `OpenDriver2/PsyCross` on this branch (untouched).

## Architecture in short (how the pieces fit)
- Game loop and states: `main.c` runs a state machine (`state.c`, `STATE_INITFRONTEND` -> `STATE_FRONTEND` -> `STATE_GAMESTART` (`glaunch.c State_GameStart`, switch on `GameType`) -> `STATE_GAMELAUNCH` -> `STATE_GAMEINIT` -> game loop -> `State_GameComplete` -> frontend again). A game is fully described by `GameType` (`dr2types.h GAMETYPE`), `GameLevel` (city, 0..3 Driver 2, 4..9 Driver 1) and `gCurrentMissionNumber`; after a game the frontend restarts at the main menu (`ReInitFrontend`).
- Missions: a D2MS file (`MS_MISSION` header of 33 ints, 16 `MS_TARGET` of 64 bytes, script words, strings; layout in `dr2types.h`, writer in `d1dlc/d1_missions.cpp`) loaded by `LoadMission` (`mission.c`; Driver 2 from `MISSIONS\MISSIONS.BLK` or a loose `MISSIONS\M<n>.D2MS`, Driver 1 from `..\DRIVER1\CONVERTED\`). The script is a small stack VM (`MRCommand` / `MROperator` / `MRFunction`, one thread per `MissionThreads` entry); targets are handled in `MRProcessTarget` (Point, Car, Event). `HandleMissionThreads` runs every frame; completion goes through `SetMissionComplete` -> `SetMissionOver` -> pause menu (`pause.c`, `EnablePause`).
- Frontend (`Frontend/FEmain.c`): screens are `PsxScreens[]` (0..39 read from `DATA\SCRS.BIN`, 40+ built in code, max 8 buttons each). A button = `action` (`FE_MAKEVAR(BTN_NEXT_SCREEN | BTN_START_GAME | ..., screen)`) + `var` (`FE_MAKEVAR(code, value)`, applied by `SetVariable` before the action runs). A screen with a `userFunctionNum` (`fpUserFunctions[]`, 1 based) is called with `bSetup = 1` when it opens (build buttons there; `BuildButtonsVertical`) and with 0 on every key press (return 1 = key handled). `ScreenNames[]` is the breadcrumb under the menu. Test the frontend without keys: `-festeps` (see below).
- Cities and levels: a `.LEV` lump file per city (`system.c SetCityType`, `spool.c`); Driver 1 cities are converted at first use by `d1dlc/` (`D1Dlc_ConvertCity`, stamp `<NAME>.VER`, version `D1DLC_CONVERTER_VERSION`) and borrow textures, car models and the sky from Driver 2 (`BASE_CITY`). Driver 1 missions are a second, separate converter (`d1_missions.cpp`, stamp `MISSIONS.VER`, `D1MISSION_VERSION`) so a mission problem never touches a city.
- Isolation rule for every Driver 1 feature: gated by `IS_DRIVER1_CITY(GameLevel)`, `IS_DRIVER1_MISSION(n)` or `GameType == GAME_DRIVER1MISSION`, never changes a Driver 2 code path, has a kill switch or a missing-data fallback, and logs instead of failing.
- Where research lives: `dev-notes/*.md` (read section 0 first), reverse engineering of the Driver 1 executable in `<parent folder>\_ref\d1exe` (Ghidra project, `all.c` = 1036 decompiled functions, `d1.bin` = the EXE image; file offset = address - 0x10000 for the kuseg addresses such as `0x8b7ac`), format scripts in `src_rebuild/tools/d1conv/spike/`.

## Tips and tricks
- Names: new code uses descriptive method names that say the Driver 1 concept (`ApplyArrivalRulesToPointTarget`, `AddPendingPointTarget`), and the top of a new file lists where to find what; keep that when you extend it.
- Several Claude sessions share this working tree: build in a private copy (`robocopy src_rebuild <copy> /E /XD build bin obj .vs __pycache__ dependencies lib`, copy `dependencies` once WITH its lib folders, run `premake5 vs2022`, `MSBuild ... -p:OutDir=<private test install>`), stage only your own hunks (`git diff -U0 -- <file>` filtered by hunk, `git apply --cached --unidiff-zero`), re-read a file that "changed on disk" before editing it.
- Private test install: `GameTestInstall\REDRIVER2_D1M` (junction `DRIVER2`, own `DRIVER1` with `LEVELS`, `DATA`, `MISSIONS\MISSION.BLK`, own `config.ini`). The Driver 1 disc used for development is `E:\DRIVER` (not part of the repo, never copied into it).
- Test without a person at the keyboard: `-d1mission <n>` (a Driver 1 story mission), `-festeps "SESDDDDSE"` (scripted frontend input: E select, D down, U up, T back, S screenshot `FESHOT<n>.BMP`, one step every 120 frames), `-shot <frame>` (in game screenshot + log lines), `-startpos x z` (start on a target to test completion). NEVER inject key events with `keybd_event` / SendKeys: they go to the focused window, which can be another session.
- Scripts with backslashes: write them to a file with the Write tool; an inline heredoc or `python -c` eats `\` (it broke `"DRIVER1\CONVERTED"` once). Repo sources are CRLF: check `d.count(b"\r\n") == d.count(b"\n")` after a script edit.
- Python prototype first, then C++: `d1mission_to_d2ms.py` is the quick place to try a conversion rule (`--out` writes the files, `--selftest` rebuilds all 137 real D2 missions byte for byte); port it to `d1_missions.cpp` and compare the output files with a standalone build (`cl /EHsc /I d1dlc main.cpp d1dlc\d1_missions.cpp`, a small driver that writes the 44 conversions).
- Reading decompiled Driver 1 code: handlers are reached through jump tables, gp-relative globals show as `unaff_gp + offset`; find a global by its address (`grep -n 968c8 all.c`) and look at who reads it. Script variables: 72 entries `{type, global, ?, default}` at file offset 0x7b7ac of `d1.bin`, global 0 = script-local variable.

## Driver 1 DLC findings (read before touching converter or renderer; details in `dev-notes/driver1-cities.md`)
- Heights: engine `MapHeight` is positive = up (`pedest.c`: `position.vy = -98 - MapHeight`), cell objects are negative = up. `D1HeightField::Eval` flips at the end. Wrong sign is invisible on flat ground: always test the Frisco hill.
- Slope planes: engine normal = `(a, b, c) >> 2` must have length 16384 (`b = 16384 / sqrt(1 + sx² + sz²)`, `b <= 16383` because `b == 0x4000` means flat). A short normal weakens `wheelforces.c` suspension and the car sinks. Quantise the slope first (plane budget ~2040 per region). Plane data must be 4 byte aligned (`spool.c` PVS buffers), else `sdGetCell` returns the sea plane.
- Pavements (`MODEL_FLAG_PATH`) stand 25-57 units above the road map height; `Eval` adds the model top (`topY`).
- Grass/water tiles lie coplanar under road tiles: `draw.c` pushes them back with `PGXP_SetZOffsetScale(0, 1.01)`. Polygons with texture page 0xFF are untextured and skipped.
- Lane markings / zebra crossings are D1 polygon type 17 (flat coloured quad) in near-detail tile models: drawn by `tile.c DrawFlatTileQuad` (was read as textured quad: green palm/grass texels).
- Start positions per city: `g_D1DlcCities` (`startX/startZ/startRotation`), used for Take a Ride in `mission.c`. Bump `D1DLC_CONVERTER_VERSION` after any converter output change.
- Testing without disturbing the user: `test_scripts\shot_safe.ps1 -City <n> -StartX -StartZ -Frame -Extra "-startrot <r>"` (game option `-shot <frame>` writes `SCREENSHOT.BMP`/`VRAM.TGA` and logs `shot:` lines: player, ground height, camera, `car N above the ground` should be about 30). `D1Conv.exe convert|probe` in the test install checks conversions (`0 problems`, `heights: ok`). Frisco hill: `-city 5 -startpos -11250 240000 -startrot 1024`.
- Car park (Part 6, in progress): a D1 city has the cop car (D1 model 0), civilians 1 and 2 (shared pages, 4 colour variants) and 4-5 player cars (D1 models 5 and up, 2 own texture pages each, 4 damage texture sets). The converter moves the player cars to the D2 numbers 8 and up (`ConvertCarModels`, table only, model data untouched), writes the D1 palettes in the D2 PALLET layout (`ConvertPalettes`) and keeps the D1 page numbers. The engine builds `carTpages` per D1 city from the car models (`D1SetupCarTpages`, called in `LoadGameLevel` BEFORE `LoadPermanentTPages`, the palette lump needs it): index 0 = page with JEANS1 (pedestrian palettes share `civ_clut[0]`), 1..5 = car pages, the rest -1. Missing colour variants show the base colour (`texture.c`, end of `LoadPermanentTPages`).
- D1 civilian cars have `num_point_normals == 0` (the player cars have normals): without a fallback every vertex shades to colour 0 and the car is a black silhouette. `ComputeCarLightingLevels` (cars.c) now shades by the direction from the car centre. The D2 damage zones (DEN of the borrowed city) list D2 vertices: they are cleared for D1 cities (`LoadDenting`), so D1 cars do not dent yet.
- D1 cars are about 1.5x the size of D2 cars (half length 576 against 375), like the D1 world (cell 3000 against 2048). Since 2026-10-11 the car MODELS are shrunk back to the D2 length (`ShrinkCarModel`: vertices + bounding sphere of clean/damaged/low models, factor `colBox.vz / maxZ`), because Tanner and the pedestrians (D2 donor) looked tiny next to 1.5x cars; the D1 world stays D1 scale. `D1ScaleCarCosmetics` (cosmetic.c, called after `ProcessCarModelLump`) takes the D2 cosmetics of the same model number from the borrowed LCF and scales every position (lights, wheels x/z, collision points, wheel size) by the ratio of the D1 model size to the D2 `colBox`; D2 sets `colBox` to the half size of the model. `cog.vy = -(lowest vertex + 5 + wheelSize / 4)` (body lower edge at wheel centre height), wheel track x 98% (20% was too narrow, tested by eye). The camera distance comes from `colBox`. Check by eye with `-shot` and `-camangle 3072` (side) / `2560` (rear quarter), zoom with a crop.
- D1 cities have no player-car texture pages yet: `SetupResidentModels` (mission.c) maps every resident model above 2 to 1/2, the car select list (`CarSelectable`, FEmain.c) offers only models 0..2, `texture.c` guards the special slot index. Test option `-camangle <n>` (2048 = behind, 3072 = from the side) shows a car from another side in `-shot` runs.
- Still open for cars: player cars (VRAM has 19 texture slots, D1 cities already use 12-14 for permanent pages, 2 more for special pages starve the area pages), car select pictures, damage from the D1 damaged model.
- Tanner shadow in D1 cities (fixed 2026-10-11): `InitTannerShadow` (motion_c.c) renders Tanner into a 64x128 VRAM window; D2 uses the lower half of slot `nperms + 1`, D1 has no such page and the window overwrote an area page (garbled shadow on walls and ground). D1 cities have exactly one spare texture slot (18): the window goes there and `tannerShadow_texture.coords` are overridden to (0,128)-(255,255).
- Pedestrians in D1 cities (fixed 2026-10-11): ped palette variants live in `civ_clut[0][texnum][pal]`; in D1 the body textures sit on the JEANS1 page but forearm/head textures on a donor page, so the variant index collided and hands/heads/jeans were speckled or grey. `PedPaletteUsable()` (motion_c.c) skips a variant when its palette slot is empty. Heads: D1 levels contain their own `PEDHEAD1` (and `CLEANWHEEL`), so the converter's "skip donor model if the city already has the name" kept the D1 head: it floated above the D2 neck with black hair/face. `d1_convert.cpp` now replaces `PEDHEAD1` by the D2 donor head (converter version 18). - Draw distance 2026-10-13 (supersedes radius 31 above): mode 2 "10x" is the old unlimited mode, radius 63 cells; the old radius-31 10x was removed. Mode 2 thins far objects beyond `FAR_THIN_RING` 16 (`FarObjectCulled`/`ObjectAccepted`), spends at most `gFarBudget` 10500 polygons (`-farbudget N`; dense Chicago ~10 ms) and clips at `farClipLimit` 6144 + 4096 * 66. `ViewDrawDistance()` still caps cars and pedestrians at radius 31. Limits raised for it: `PRIMTAB_SIZE` 0x80000, `OTSIZE` 0x8000 (depth index `z >> 1` of far cells overflowed the older tables), `MAX_DRAWN_TILES` 4000; PsyCross has a fmod cache. PsyCross `MAX_VERTEX_BUFFER_SIZE` is 65536 and `ParsePrimitive` does not bound check it (measured peak ~47K at crowd 5, map primitive bytes up to 361K). The map walk only collects lists: primitives are built later in `DrawTILES`/`DrawAllBuildings` (they stop below 60000 bytes free) and cars skip below ~8800 bytes free; the OT is drawn far to near, so an overflow drops the NEAREST things.

## Conventions
- Source files are CRLF (some with UTF-8 BOM, e.g. `redriver2_psxpc.cpp`); keep them. New files: CRLF, no BOM.
- A C++ `//` comment must not end with a backslash (Windows paths): it swallows the next line.
- Commit messages: no Co-Authored-By trailer (user rule). Do not stage `src_rebuild/build`, `dependencies`, `premake5.exe`, `bin`, `lib`.
- Editing C/C++ with scripts: never put \n inside an inline heredoc or `python -c` (the shell collapses the backslash, so a string literal such as `printInfo("...\n")` ends up with a real line break; it went wrong several times). Write the script to a file with the Write tool and build the escape with `chr(92) + "n"`, or use the Edit tool on a single line. Most sources are CRLF: check with `python -c` or a script (`d = open(p, "rb").read()`, count `b"\r\n"` against `b"\n"`, equal = pure CRLF), use the file own newline in multi-line anchors and replacements, and read and write bytes, never text mode.
- Several sessions share this working tree: stage only your own hunks (`git add -p`), never `git add -A`.
- Frontend option toggles live in Options - Gameplay - Secret (`CheatScreen`, `FEmain.c`): add a row to its `rows[]` table, a code-built screen (`PsxScreens[n]`, `PsxScreens[49]` ends at 48), a `FEVAR_*` var code (21 is the highest in use, check the `#define`s) and, to persist, a `CONFIG_SAVE_HEADER.reserved[]` slot in `loadsave.c`: all six are taken, so pack new values into the upper bits of an existing slot (e.g. `reserved[1]` holds only 0/1). Details: `dev-notes/camera-orbit.md` section 0b.
- Stick camera (`UpdateCameraOrbit`, camera.c, plan `dev-notes/camera-orbit.md`): the right stick turns (yaw) and raises or lowers (pitch, -120..380 units) the chase camera around the car, look back eases to half a turn (`camLook`) instead of snapping, and after `cameraReturnDelayMs` (1000) without input the offset returns exponentially (soft start, snap below 8 units). State per player: `camYaw`, `camPitch`, `camLook`, `camIdle`; all zero in cutscenes, replays, on foot, with the option off (Options - Gameplay - Secret - Extended Settings - Free Camera, `reserved[5]`) so the original camera is untouched. `config.ini [game]`: `cameraAutoCenter`, `cameraReturnDelayMs`, `cameraStickSensitivity`, `cameraInvertY`.
